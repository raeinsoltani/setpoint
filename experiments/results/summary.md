## ⚠ These tables mix load contracts

`load_contract` records how load was delivered to the fleet. Runs marked
`shared-connections-pre-v2` were produced before the fix in lab notebook
§11.13, when k6's default keep-alive pinned every connection to one backend
pod and only 3-4 replicas served regardless of fleet size.

**Comparing across the two groups is only valid for metrics §11.15 clears:**
SLA violation %, replica-seconds, under/over-provisioning and reversal counts,
which were verified to be unaffected. Latency is not comparable across the
groups at all, and neither is any arm reading per-pod metrics (`hpa-custom`).

## Repeatability

Independent `TIME_SCALE=1` runs of the same arm on the same workload. The
tables above report the **latest** run per arm; this reports every one.

This section sets the resolution of every comparison made elsewhere: a
difference between two arms that is smaller than the spread of one arm
against itself is not a result. Values are listed individually rather than
averaged, because at n=2-3 a mean hides more than it shows.

Grouped by load contract as well as by arm: runs either side of §11.13 are
two experiments, not repeats, and pooling them would report the gap between
them as this arm's noise floor.
